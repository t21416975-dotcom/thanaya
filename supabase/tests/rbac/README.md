# اختبارات الصلاحيات المحدودة (RBAC)

مجموعة سيناريوهات SQL تتحقق من أن **الحدود تُنفَّذ داخل قاعدة البيانات** (RLS + Triggers)، لا في الواجهة.

## التشغيل

```bash
# قاعدة مؤقتة فقط (السكربت يُنشئ بيانات اختبار)
./supabase/tests/rbac/run.sh "postgresql://postgres:postgres@127.0.0.1:5432/thanaya_test"
```

السكربت بالترتيب:

1. `00_bootstrap.sql` — يحاكي بيئة Supabase: أدوار `anon` / `authenticated` / `service_role`،
   مخطط `auth`، الجدول `auth.users`، والدالة `auth.uid()` التي تقرأ `request.jwt.claim.sub`.
2. كل ملفات `supabase/migrations/*.sql` بالترتيب.
3. سيناريوهات `01..05` (كل فشل يرفع استثناءً ويوقف السكربت).

## السيناريوهات

| الملف | ما يتحقق منه |
|---|---|
| `01_fixtures.sql` | تهيئة: حسابان إضافيان، مادتان، ثلاثة موارد، امتحان، بلاغ، ومنح مقيّدة |
| `02_editor_scoped.sql` | محرر مقيّد بالفيزياء: تعديل داخل النطاق فقط، منع النشر/الحذف/النقل، منع تعديل الصلاحيات، حجب الإعدادات |
| `03_admin_preset_and_public.sql` | رتبة `admin` (قالب): تنشر لكن لا تدير الفريق/الإعدادات — مشرف بلاغات مقيّد — المدير العام — الزائر `anon` |
| `04_grants_integrity.sql` | صلاحية مؤقتة منتهية، مستخدم مسجّل بلا صف في `admins`، نطاق غير موجود، منع منح ما لا تملكه، منع المنح الذاتي، تنظيف المنح اليتيمة |
| `05_deny_and_single_resource.sql` | المنع الصريح `deny`، ومنح صلاحية على **مورد واحد** فقط |

## ملاحظات

- `psql` هو المتطلب الوحيد؛ لا يحتاج Docker ولا Supabase CLI.
- الاختبارات تفترض قاعدة نظيفة (تُدرج بيانات ثابتة)، فلا تشغّلها على قاعدة إنتاج.
- لتصفية النتائج: `./run.sh "$DATABASE_URL" 2>&1 | grep -E 'PASS|FAIL'`.
